## 0. 当前待解：云构建 exit code 为空（最高优先级）

**现象**：第一阶段 `CocosCreator.exe --build ...` 启动成功（编辑器正常初始化、Package 全部 enable），但 pwsh 的 `$LASTEXITCODE` 为**空**，脚本误判失败提前退出（exit code: 后面是空白）。

**根因分析**：Cocos Creator 3.8 的 CLI 主进程会 fork/派生构建子进程后**立即返回**（Windows GUI 程序 detach），pwsh 的 `$LASTEXITCODE` 没有被设置（GUI 程序不设置 exit code），脚本随即以 `$code = ''` 走进 `notin 0,36` 分支误杀。编辑器实际还在后台继续构建，但 job 已被终止。

**修复方案（P0-1）**：
- 不再依赖 `$LASTEXITCODE`，改用 `Start-Process -Wait -PassThru` 获取真实 ExitCode；
- 并加超时保护（第一阶段 25 分钟、第二阶段 40 分钟）；
- 构建成功的判定改为**产物导向**：第一阶段检查 `build/android/proj/` 目录生成；第二阶段检查 `*.apk` 存在。exit code 仅作日志。

**预期**：这轮修复后 CI 链路真正跑通，首次出 APK。

## 2. 算法优化（P1.5，纯逻辑可单测）

### 2.1 出牌 AI 从贪心升级为「分解 + 局面评估」
现状：`decompose()` 贪心分解 + 最小可压。问题：拆对子保顺子、炸弹时机粗糙、农民配合弱。

升级为两层：
1. **手牌分解枚举**：`decomposeAll()` 返回 top-N 种分解方案（按手数、炸弹保留度、控制力加权排序），而不是唯一贪心解
   - 权重函数：`score = -手数×10 + 炸弹保留×8 + 大牌控制×3 - 拆牌损失`
2. **跟牌决策树**（不再只取最小可压）：
   - 评估每个候选出牌后的"剩余手数变化"
   - 队友协作强化：地主下家（农民）出小单顶住，地主上家（农民）出牌喂队友
   - 终局搜索：剩 ≤4 张时做 2~3 层 minimax（分支有限，可实时算）
- **验收**：AI 自对弈 200 局，统计地主胜率应落在 45%~60%（当前贪心版预计 35% 以下）；无非法出牌、无死循环

### 2.2 记牌器与概率估计（P2）
- `CardCounter`：记录已出牌，AI 用剩余未现牌概率调整跟牌意愿（如剩 2 张 K 未现，单张 K 压制意愿提高）
- 简单贝叶斯：对手不出 → 手牌很可能连不起来 → 加大压制

### 2.3 提示功能分层（P2）
- 玩家提示从"最小可压"升级为三档：最省牌 / 最压制 / 建议过，按钮循环切换

## 风险与备注

- Cocos CLI 在 Windows runner 的行为已验证到"编辑器正常启动、Package 初始化成功"，剩余不确定性集中在：构建任务是否被我们提前误杀（本轮已证实）、stage=make 的 ndkPath 传参。产物导向判定可同时消解这两个问题。
- 场景文件是我手写的最小 YAML，编辑器首次打开若报格式问题，需要在 CI 日志里确认 scene 解析成功（本轮日志未见场景报错，风险较低）。
- AI 自对弈基准脚本进 `tests/`（node 环境即可跑，不需要引擎）。
